ARCHITECTURAL SPECIFICATION

Enabling Traversal Expansion (Option 3) in Hermes DB

In your existing system, vectors act only as entry-point routers (retrieving initial turns) and edge trust scorers (the query vs stored edge vector alignment). To enable Option 3, vectors become traversal bridges: when your graph walk hits an isolated cluster, the walker queries vector space dynamically to jump the gap.

1. Schema Prerequisite
Individual Noun Embeddings

Currently, whole-turn embeddings and edge vectors exist. Traversal expansion requires an indexed vector column on the nouns table itself with an HNSW cosine index.

2. Walker Modification
Hybrid Expansion Step

When get_neighbors(node) returns no strong co-occurrence paths or remaining budget permits, issue a scoped k-NN query over nouns.embedding.

3. Provenance & Scoring
Jump Penalty & Virtual Flag

Tag dynamic edges with virtual=true, apply a jump penalty factor (e.g. 0.85×) to beam_score, and limit jumps to 1 per path.

2. Backend Walker: Sparsity-Gated Fallback Engine Python / Hermes Retriever Engine 
def traverse_with_sparsity_fallback(current_node, query_vec, visited, min_structural_degree=1):
    candidates = []
    
    # STEP 1: Always execute verified structural co-occurrence walk first
    cooccur_edges = db.query(
        """
        SELECT target_noun, magnitude, provenance, e_src_vec, e_tgt_vec 
        FROM semantic_edge 
        WHERE source_noun = :src
        """, 
        src=current_node.id
    )
    valid_structural = [e for e in cooccur_edges if e.target_noun not in visited]
    
    for e in valid_structural:
        c = cosine_similarity(query_vec, e.e_src_vec) * cosine_similarity(query_vec, e.e_tgt_vec)
        score = (e.magnitude / 8.0) * c
        candidates.append(Candidate(node=e.target_noun, score=score, is_virtual=False, provenance=e.provenance))

    # STEP 2: SPARSITY GATE — ONLY fire vector search if the graph path is exhausted or empty
    if len(candidates) < min_structural_degree and not current_node.has_taken_fallback:
        # Issue scoped k-NN query over semantic_noun embeddings as a fallback bridge
        knn_nouns = db.query(
            """
            SELECT id, 1 - (embedding <=> :node_vec) AS sim
            FROM semantic_noun
            WHERE id != :src AND id NOT IN :visited
              AND 1 - (embedding <=> :node_vec) >= 0.78
            ORDER BY embedding <=> :node_vec ASC
            LIMIT 2
            """,
            node_vec=current_node.embedding,
            src=current_node.id,
            visited=tuple(visited)
        )
        for neighbor in knn_nouns:
            candidates.append(Candidate(
                node=neighbor.id,
                score=neighbor.sim * 0.70, # Lower priority than verified facts
                is_virtual=True,
                epistemic_notice="UNCONFIRMED_SIMILARITY_FALLBACK"
            ))

    return candidates
3. Prompt Formatter: The Epistemic Notice Pattern Prompt Constructor 
def format_hermes_context(traversed_nodes, fallback_bridges):
    output = ["## HERMES RETRIEVED MEMORY GRAPH"]
    
    # Section 1: Ground Truth Co-occurrences
    output.append("### VERIFIED CONVERSATION CO-OCCURRENCES")
    for n in [x for x in traversed_nodes if not x.is_virtual]:
        output.append(f"- [Turn #{n.turn_id}] {n.src} mentions {n.tgt} (magnitude {n.magnitude:.1f})")
        
    # Section 2: Epistemic Notice Banner (Only present if sparsity fallback fired)
    if fallback_bridges:
        output.append("\n### [EPISTEMIC NOTICE: ASSOCIATIVE SIMILARITY LEAP]")
        output.append(
            "Notice: The following connection was formed via vector embedding proximity due to sparse graph data. "
            "No conversation in the database mentions these entities together. Treat this thematic bridge with epistemic reserve:"
        )
        for b in fallback_bridges:
            output.append(f"- [UNCONFIRMED SIMILARITY] {b.src} ~~~> {b.tgt} (Cosine similarity {b.sim:.2f})")
            
    return "\n".join(output)
